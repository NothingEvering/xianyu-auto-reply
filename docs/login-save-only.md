# 仅保存登录

这个模式用来先完成账号配置和登录保存，而不启动自动回复、关键词、AI 回复、默认回复或订单自动化。

本文档和代码改动属于同一补丁，一起应用。适用的部署基线是 `4d5e2b8705af7b7e1aff2fd941ded13bb8fb2106`（原仓库「完善码支付」）。它不包含该提交之后的在线安装、商品查询或 API 关键词文档更新。

系统设置键是 `account.login_save_only`。管理界面在「基础设置」中的「仅保存登录」。没有这条设置，或值无法识别时，按开启处理。

## 开启时会做什么

扫码登录、共享扫码、账号密码登录（协议和浏览器）、手工添加账号、Excel 导入、重新登录和登录续期成功后：

- 保存 Cookie、登录账号、登录密码、unb、登录方式和最后登录时间。
- metadata 只增加 `login_save_only` 标记，并清掉 Cookie 续期快照。已有的 AI、关键词等配置会保留。日志和 metadata 不写入 Cookie 或密码。
- 新账号写入 `disabled`，禁用原因是「仅保存登录，未启用自动任务」。
- 已经禁用的账号保持禁用；原来的禁用原因还在时继续保留。
- 登录前是 `active` 的旧账号也会改成 `disabled`。旧的启用状态不会写回去。
- 导入表格里的「启用」和「全部启用」都不会把账号改成启用。
- 不调用账号任务的 start 或 restart。已有账号重新登录时，只请求停止可能还在运行的连接。
- 不调用发消息或创建会话接口。

Cookie 文本更新只写数据库，不重启连接。WebSocket 服务重启时只调度状态恰好为 `active` 的账号，因此禁用账号不会在重启后自动连接。

调度器里的关键词、默认回复、AI 回复和订单类任务只查询启用账号。仅保存登录开启时，Cookie 续期任务会跳过禁用账号，不会把它们改回启用；接口续期即使发现账号已被禁用，也不会重新启用或启动连接。

## 手动启用之后

仅保存登录不改变账号管理里的手动开关：

1. 保持 WebSocket 和 scheduler 停止，完成登录、导入、关键词、默认回复和 AI 配置。
2. 准备让某个账号自动处理时，先启动 WebSocket 服务。需要定时补发货、补评价、擦亮、订单拉取或续期时，再启动 scheduler。
3. 在账号管理中把该账号设为启用。启用会立即调用 WebSocket 服务启动这个账号的连接。
4. 如果 WebSocket 服务还没启动，启用请求会失败，状态回滚为禁用，不会留下一个“已启用但服务未运行”的账号。
5. 启用成功后，该账号按已保存的关键词、默认回复、AI 回复和订单开关工作。服务重启时，这个 `active` 账号会被重新调度。

模式仍然开启时，该账号再次登录会重新保存为禁用，并停止已运行的连接。要恢复“登录成功即启用并启动任务”的原行为，先关闭「仅保存登录」并保存基础设置。关闭后，新的登录、导入和续期才按原来的启用并启动逻辑执行；已经禁用的账号不会因为关闭开关而自动变成启用。

## 建议的模型配置

AI 回复在账号管理中按账号保存。可以选择 OpenAI 兼容，接口地址填 `https://www.micuapi.ai/v1`，模型名填 `deepseek-v4-flash`。API Key 只填在管理界面中，不要写入仓库、补丁、环境文件或日志。账号保持禁用时，保存这些配置不会发送消息。

## 当前部署

只运行 mysql、redis、backend-web 和 frontend，并且 WebSocket 与 scheduler 未启动时，打开本模式后可以安全添加账号。后端重启后会补上缺失的设置项；在补上之前，登录路径也会把缺失设置视为开启。
